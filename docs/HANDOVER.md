# HANDOVER — состояние проекта БОС · Аналитика

Короткая карта проекта для новой сессии/устройства. Читать целиком (~2k токенов) вместо
разбора исходников.

## Где что

- Репозиторий: https://github.com/ka2106/b0s.git, ветка `main` — рабочая версия, тег `v1.0`.
- Прод: https://ka2106.github.io/b0s/ (GitHub Pages из `main`, корень). На 24.11.2026
  `main` = `4af39d5`, прод побайтово совпадает с локальными `app.js`, `index.html`, `styles.css`,
  `config.js` (сверять так: `Invoke-WebRequest` файла с Pages → сравнить строки после
  нормализации `\r\n`, длина должна совпасть).
- Локально: `npx serve -l 5173 .` → http://localhost:5173 (не `file://`, иначе карта без Referer).
- Файлы: `index.html` (разметка 4 вкладок), `styles.css` (стили, тёмная тема, печать),
  `app.js` (вся логика, ~3.2k строк, IIFE, классический скрипт), `config.js` (ключ карты,
  публичный, ограничен Referer), `docs/setup-new-device.html` (инструкция с нуля), `README.md`.

## Ключевые решения и грабли

- **Данные**: публичная Google-таблица через gviz (`CONFIG.sheetId`, лист `data`), кэш 10 мин,
  автообновление 5 мин, кнопка «Обновить» сбрасывает кэш.
- **Карта**: ключ Яндекс JS API в `config.js` (продукт «JavaScript API», не Static/MapKit/Tiles).
  В кабинете Яндекса Referer обязан включать `ka2106.github.io`, `paragulgov.ru`, `localhost`,
  `127.0.0.1`. Ключ без домена в списке → `Invalid API key`. Лимит 100 загрузок/сутки считается
  локально (`localStorage["bos_map_usage"]`), есть кнопка «Загрузить всё равно».
- **Тайлы**: рисуются в `<canvas>` внутри `ground-pane`; проверка «загрузились ли» должна смотреть
  и в `img`, и в `canvas` (уже исправлено в `app.js`).
- **Координаты**: `cityCoords` в `app.js`, 86 записей, формат `"Город": [lat, lng]`;
  поиск через `normName()`/`coordsFor()` (алиасы, скобки, суффиксы этапов).
- **Статусы**: `STATUS_CONF` / `STATUS_ALIASES` / `canonicalStatus()`; неизвестные не ломают UI.
- **Этапы и АБЧ**: этап = строка, где категория/этап не содержит «АБЧ» (СЦ, промпарк,
  производство, БВС — этапы). Правило живёт в `isAbchRow` (дашборд) и в `updateMap` (карта) —
  держать их согласованными.
- **KPI**: «Всего объектов» = уникальные `obj`, под ним «N этапов · M АБЧ» и раскладка статусов
  по этапам. Клик по карточкам «Сдано/Осталось» фильтрует таблицу по статусу + текущему году.
- **Фильтры**: `FILTER_KEYS = fo, obj, category, status, year`; год — бакеты
  «Ранее / 2024…текущий / Далее / Без даты» (`yearBucket`, `YEAR_RANK`). Годы на графике и в
  таблице сдачи кликабельны (`drillDownYear`).
- **Таблица**: ширины колонок в px через `<colgroup>` (`COLUMN_DEFS[].w`), `table-layout: fixed`,
  ellipsis + `title`; закреплены шапка и первый столбец (вертикальной полосы нет); контейнер
  высотой `calc(100dvh - 112px)`, горизонтальный скролл внутри него.
- **Экспорт Excel**: ExcelJS с CDN + SRI, листы «Сводка» и «Выборка», гиперссылки РВ.
- **Прочее**: тёмная тема через `prefers-color-scheme`, печать (`@media print`), мобильный
  drawer фильтров, состояние в `localStorage["bos_analytics_state"]`.

## Карта: «фризит при зуме» — что уже проверено (24.11.2026, не закрыто)

Симптом от пользователя: при приближении карты (например, Москва) всё подвисает, работать
невозможно. Правка `f187822` (SVG-метки вместо DOM-шаблонов) проблему не подтвердила.

Измерено на проде и локально (`localhost:5173`), Chromium 150 (встроенный в VS Code), dpr 1:
- зум `map.setZoom(10…19)` и колесом: ровные 60 fps, p95 ≈ 7 мс, long tasks = 0; то же при
  троттлинге CPU ×4–6 через CDP `Emulation.setCPUThrottlingRate`;
- headless Chrome с `--disable-gpu` (софт-рендер), 1400×900 и 2560×1400 при dpr 1 / 1.25 /
  1.5 / 2 (канвас Яндекса до 9 Мпикс): 60 fps, отдельные пики 35–45 мс, long tasks = 0;
- сеть: все тайлы 200, ретраев/403 нет; `ymaps` грузится один раз;
- при зуме метки не пересобираются (MutationObserver = 0 мутаций); в простое
  `TaskDuration` = 0, heap ≈ 17 МБ, узлов в `#map` ≈ 258; «Обновить» и переключение вкладок —
  без long tasks.

Вывод: аппаратно-независимого узкого места в нашем коде не найдено. Нужны данные окружения
пользователя: браузер, включено ли аппаратное ускорение (`chrome://gpu`), dpr/масштаб Windows,
замирает вся вкладка или только карта, с какого зума. Кандидаты: софт-рендер/слабая графика,
Firefox/Safari, дробный dpr (1.25/1.5), очень большой экран, а также старый `app.js` из кэша
Pages (`max-age=600`: у HTML есть `?t=`, у `app.js` — нет, помогает Ctrl+F5).

Как мерить при следующей сессии (не тратить время заново):
- получить экземпляр карты: `page.addInitScript` ставит setter на `window.ymaps` и оборачивает
  `ymaps.Map`, сохраняя инстанс в `window.__map`; работает, только если вкладка «Карта» не
  активна на момент загрузки (иначе карта создаётся раньше ловушки).
- софт-рендер и DPI: `playwright-core` + системный Chrome, `--disable-gpu`,
  `newPage({ viewport, deviceScaleFactor })`, статический сервер на `localhost:5173`
  (ключ разрешён по Referer для localhost).
- метрики: rAF-разрывы + `PerformanceObserver('longtask')`, `CDP Performance.getMetrics`.

## Правила работы (экономия токенов)

- Не читать файлы целиком: `grep` + `view` с диапазоном строк.
- Не вызывать браузерные «снимки страницы» и скриншоты без нужды; вместо них короткие проверки
  (`page.evaluate` с маленьким JSON).
- Править через `edit`/точечные скрипты, проверять `node --check app.js` и `git diff --stat`,
  не перечитывая файлы повторно.
- Коммит после каждого логичного шага; ветка от `main`, затем `--ff-only` merge и push.
- Если контекст сессии перевалил ~60–80k токенов — зафиксировать состояние здесь и продолжить
  в новой сессии, начав с фразы «прочитай docs/HANDOVER.md».
