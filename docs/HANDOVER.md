# HANDOVER — состояние проекта БОС · Аналитика

Короткая карта проекта для новой сессии/устройства. Читать целиком (~2k токенов) вместо
разбора исходников.

## Где что

- Репозиторий: https://github.com/ka2106/b0s.git, ветка `main` — рабочая версия.
  Актуальный релиз — тег `v1.1` (26.11.2026), предыдущий — `v1.0`.
- Прод: https://ka2106.github.io/b0s/ (GitHub Pages из `main`, корень), деплой ~1 минута.
  Актуальный хеш — `git log -1`; сверять прод с локалем через `Invoke-WebRequest` файла
  с Pages и нормализацию `\r\n`.
- Локально: `npx serve -l 5173 .` → http://localhost:5173 (не `file://`, иначе карта без Referer).
- Файлы: `index.html` (разметка 4 вкладок), `styles.css` (стили, тёмная тема, печать),
  `app.js` (логика: данные, фильтры, таблица, карта, сравнение, экспорт; ~3.2k строк, IIFE,
  классический скрипт), `coords.js` (координаты площадок, `window.BOS_COORDS`),
  `debug-hud.js` (оверлей `?debug=1`, `window.BOS_DEBUG_HUD`), `excel-loader.js` (ленивая
  загрузка ExcelJS, `window.BOS_EXCEL`), `config.js` (ключ карты, публичный, ограничен
  Referer), `docs/setup-new-device.html` (инструкция с нуля), `README.md`, `docs/WORK-RULES.md`,
  `docs/IDEAS.md` (отложенные идеи и список отклонённых направлений).

## Ключевые решения и грабли

- **Тема**: переключатель «системная → светлая → тёмная» (`localStorage["bos_theme"]`).
  Тёмная тема включается атрибутом `data-theme="dark"` на `<html>`; инлайн-скрипт в `<head>`
  ставит его до загрузки CSS, поэтому мигания нет. `prefers-color-scheme` в CSS больше не
  используется — режим «системная» разрешается в JS.
- **Отчёт PDF**: меню «Отчёт PDF» (три режима: `all` / `dashboard` / `table`) ставит на
  `<body>` классы `printing-report` и `print-mode-…`, затем `window.print()`. Печатный CSS
  задаёт `@page { size: A4 landscape }`, скрывает карту, сравнение, поиск, панель действий и
  меню, сжимает KPI/графики и растягивает реестр на всю ширину страницы (шапка таблицы
  повторяется на каждой странице, итоги не липнут). Заголовок, выборка и дата данных
  подставляются в `beforeprint`.
  Поля листа — `@page { margin: 10mm 12mm }` плюс `padding: 0 5mm` у `.container`: запас
  сохраняется, даже если в диалоге выбраны минимальные поля. Для портретной печати есть
  fallback (`@media print and (orientation: portrait)`): KPI 2×2, графики в одну колонку,
  реестр мельче (8 px) — чтобы браузер не масштабировал страницу и текст не «мылился».
  Цвета: `print-color-adjust: exact` задаётся на `body.printing-report *` (свойство не
  наследуется), плашки статусов получают цветные фоны, тени отключены. Типографика печати:
  11 px базовый, 10 px реестр, целые кегли и `-webkit-font-smoothing: auto` — мелкий
  Inter со сглаживанием «в толщину» в PDF выглядел бледным.
  **Ширина полосы набора равна ширине листа** (A4-портрет ≈ 700 px), поэтому в печати
  срабатывают мобильные правила `max-width: 768px` — без сброса шапка таблицы уезжала за
  край, строки становились «плитками» (`td::before` с подписями, пустые ячейки скрыты,
  первая ячейка `display: block`), а отчёт раздувался с 12 до 69 страниц. В печатном блоке
  есть сброс: таблица остаётся таблицей, подписи скрыты, пустые ячейки не прячутся,
  `min-width` реестра снят, `.cell-title/.cell-sub` переносятся. Кегль в печати задаётся
  на `th`/`td`, а не на `table`: базовое `td { font-size: 12px }` перебивает размер таблицы.
  `@page` — одно правило верхнего уровня (`size: A4 landscape`), не внутри `@media print`.
  Проверено headless-Chrome (`Page.printToPDF`, `preferCSSPageSize`): «Сводный отчёт» —
  A4-альбом 842×595 pt, 12 страниц, реестр без обрезки столбцов при ширине полосы 603–972 px.
- **Таблица**: строка итогов (`tfoot`, закреплена снизу) суммирует видимые числовые столбцы
  по текущей выборке; поиск (`state.search`) работает вместе с фильтрами.
- **Фильтры**: «Сбросить фильтры» и чипы «Выборка» (`#table-context`) снимают отдельный
  фильтр или все сразу.
- **Данные**: публичная Google-таблица через gviz (`CONFIG.sheetId`, лист `data`), кэш 10 мин,
  автообновление 5 мин, кнопка «Обновить» сбрасывает кэш.
- **Офлайн-копия**: последняя удачная загрузка пишется в `localStorage["bos_analytics_snapshot"]`;
  при недоступности Google показывается она, в шапке — «офлайн-копия от ЧЧ:ММ», плюс тост.
- **Карта**: ключ Яндекс JS API в `config.js` (продукт «JavaScript API», не Static/MapKit/Tiles).
  В кабинете Яндекса Referer обязан включать `ka2106.github.io`, `paragulgov.ru`, `localhost`,
  `127.0.0.1`. Ключ без домена в списке → `Invalid API key`. Лимит 100 загрузок/сутки считается
  локально (`localStorage["bos_map_usage"]`), есть кнопка «Загрузить всё равно».
- **Тайлы**: рисуются в `<canvas>` внутри `ground-pane`; проверка «загрузились ли» должна смотреть
  и в `img`, и в `canvas` (уже исправлено в `app.js`).
- **Координаты**: `cityCoords` в `app.js`, 86 записей, формат `"Город": [lat, lng]`;
  поиск через `normName()`/`coordsFor()` (алиасы, скобки, суффиксы этапов).
- **Статусы**: `STATUS_CONF` / `STATUS_ALIASES` / `canonicalStatus()`; неизвестные не ломают UI.
- **Этапы и АБЧ**: этап = строка, где категория/этап не содержит «АБЧ» (СЦ, промпарк,
  производство, БВС — этапы). Правило живёт в `isAbchRow` (дашборд) и в `updateMap` (карта) —
  держать их согласованными.
- **KPI**: «Всего объектов» = уникальные `obj`, под ним «N этапов · M АБЧ» и раскладка статусов
  по этапам. Клик по карточкам «Сдано/Осталось» фильтрует таблицу по статусу + текущему году.
- **Фильтры**: `FILTER_KEYS = fo, obj, category, status, year`; год — бакеты
  «Ранее / 2024…текущий / Далее / Без даты» (`yearBucket`, `YEAR_RANK`). Годы на графике и в
  таблице сдачи кликабельны (`drillDownYear`).
- **Таблица**: ширины колонок в px через `<colgroup>` (`COLUMN_DEFS[].w`), `table-layout: fixed`,
  ellipsis + `title`; закреплены шапка и первый столбец (вертикальной полосы нет); контейнер
  высотой `calc(100dvh - 112px)`, горизонтальный скролл внутри него.
- **Экспорт Excel**: ExcelJS с CDN + SRI, листы «Сводка» и «Выборка», гиперссылки РВ.
- **Прочее**: тёмная тема через `prefers-color-scheme`, печать (`@media print`), мобильный
  drawer фильтров, состояние в `localStorage["bos_analytics_state"]`.
- **Диагностика**: `?debug=1` — оверлей (`initDebugHud`, стиль `.perf-hud`) с fps, худшим кадром,
  long tasks, тайлами (сред/макс/>500 мс), heap, размером canvas, числом маркеров и zoom.
  Выключен по умолчанию, на обычную работу не влияет.

## Карта: «фризит при зуме» — отложено (закрыто 24.11.2026 по решению владельца)

Не воспроизводится на рабочем ПК и к нашему коду не привязано. Новую сессию просить не нужно,
пока владелец сам не вернётся с данными по проблемному устройству.

Измерено на проде и локально (`localhost:5173`), Chromium 150 (встроенный в VS Code), dpr 1:
- зум `map.setZoom(10…19)` и колесом: ровные 60 fps, p95 ≈ 7 мс, long tasks = 0; то же при
  троттлинге CPU ×4–6 через CDP `Emulation.setCPUThrottlingRate`;
- headless Chrome с `--disable-gpu` (софт-рендер), 1400×900 и 2560×1400 при dpr 1 / 1.25 /
  1.5 / 2 (канвас Яндекса до 9 Мпикс): 60 fps, отдельные пики 35–45 мс, long tasks = 0;
- при зуме метки не пересобираются (MutationObserver = 0 мутаций); в простое
  `TaskDuration` = 0, heap ≈ 17 МБ, узлов в `#map` ≈ 258; «Обновить» и переключение вкладок —
  без long tasks.

Дополнительно проверено: сеть (тайлы 200, среднее 25 мс, макс 123 мс, 0 ошибок; gviz 0,7 с;
page load 69 мс), GPU проблемного ПК (GTX 1080 Ti, ANGLE/D3D11, ускорение включено) и данные
(68 объектов → 68 уникальных координат, точных наложений нет; 13 групп в `cityCoords` — только
алиасы; 4 пары объектов ближе 1,4 км: Алексин/Алексин 2, Краснодар/Краснодар ПромПарк,
Екатеринбург/Екатеринбург 2, Рязань/Рязань (Производство) — сливаются только на мелком зуме).

На слабых устройствах (2 браузера + телефон, в т.ч. на мобильном интернете) воспроизвести не
удалось. Гипотезы, если возвращаться: дробный зум на тач (в API `avoidFractionalZoom` включён
только для десктопа), плотные тайлы Москвы на z16+, 68 слоёв-иконок на слабом GPU. Шаги по
порядку: `map.options.set("avoidFractionalZoom", true)` → ограничение зума 17 → `ymaps.Clusterer`;
проверять одной выкаткой с флагами адреса, а не серией деплоев.

Если снова попросят «починить фризы» — сначала скриншот панели `?debug=1`, без него не гадать.
Учесть: в VS Code-браузере невидимая вкладка троттлится до ~2 fps без long tasks — это не карта.

Как мерить при следующей сессии (не тратить время заново):
- получить экземпляр карты: `page.addInitScript` ставит setter на `window.ymaps` и оборачивает
  `ymaps.Map`, сохраняя инстанс в `window.__map`; работает, только если вкладка «Карта» не
  активна на момент загрузки (иначе карта создаётся раньше ловушки).
- софт-рендер и DPI: `playwright-core` + системный Chrome, `--disable-gpu`,
  `newPage({ viewport, deviceScaleFactor })`, статический сервер на `localhost:5173`
  (ключ разрешён по Referer для localhost).
- метрики: rAF-разрывы + `PerformanceObserver('longtask')`, `CDP Performance.getMetrics`.

## Правила работы и экономия токенов

Полный свод правил — [`docs/WORK-RULES.md`](WORK-RULES.md) (экономия токенов, обязательное
согласование действий, коммиты и пуши только по «да»).

Старт новой сессии: «прочитай docs/HANDOVER.md» — этого достаточно, исходники целиком не нужны.

- **Объёмные операции — только после согласования**: план (что/зачем/риск) → «да» → делаем.
  Объёмное: выкатка в прод, правки > ~50 строк или нескольких файлов кода, рефакторинг,
  установка пакетов, тестовые стенды и замеры производительности, новые файлы, изменения
  UX/поведения, всё, что требует ручной проверки владельцем. Без согласования — чтение/поиск,
  мелкие правки и доки внутри уже согласованной задачи.

- Не читать файлы целиком: `grep` + `view` с диапазоном строк (`app.js` ~3.4k строк).
  Не перечитывать файл, который уже в контексте.
- Браузер: `page.evaluate` с маленьким JSON вместо «снимков страницы» и скриншотов; скриншот —
  только когда нужно увидеть UI.
- **Не переизмерять производительность карты**: цифры в разделе про карту актуальны. Стенд
  (playwright-core + Chrome + `localhost:5173`) поднимается за 2 минуты, но только по запросу.
- Спорные гипотезы — сначала обсудить и получить «да», потом одна выкатка. Вместо серии деплоев
  делать один с флагами адреса (`?afz=1`, `?zoomcap=17`, `?cluster=1`) и просить владельца
  сравнить ссылки.
- Правки — батчем (`edit` ×N в одном ответе), затем `node --check app.js` и `git diff --stat`;
  после каждой строки файл не перечитывать. Доки — без сборки и прогонов.
- Логи, диффы и поиск — сжато: `--stat`, первые N строк, `Select-String` вместо полного вывода.
- Деплой: Pages собирается из `main` ~1 минуту; сверять прод с локалем одной командой
  (см. «Где что»), а не глазами по файлам.
- Коммит после каждого логичного шага; ветка от `main`, затем `--ff-only` merge и push.
- Если контекст перевалил ~60–80k токенов — дописать сюда состояние и начать новый чат.
