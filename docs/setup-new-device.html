1. Что это за проект

Одностраничный дашборд строительства складов. Это статические файлы: нет сборки, нет npm install, нет серверной части. Достаточно открыть index.html — но надёжнее через локальный веб-сервер (шаг 5).

Файл Назначение
index.html Разметка всех вкладок: Дашборд, Таблица, Карта, Сравнение
styles.css Все стили, включая тёмную тему и печать
app.js Логика: загрузка Google Sheets, фильтры, таблица, карта, экспорт в Excel
config.js Ключ Яндекс.Карт (публичный, ограничен по домену в кабинете Яндекса)

Репозиторий: https://github.com/ka2106/b0s.git, основная ветка — main. Любая новая работа начинается от main.

2. Установка инструментов

Все команды ниже — для Windows в PowerShell (меню «Пуск» → введите PowerShell). Для macOS/Linux — примечания в конце шага.

2.1. Git

winget install --id Git.Git -e --source winget

Проверка (может понадобиться перезапустить PowerShell):

git --version

Представьтесь Git — это попадёт в коммиты:

git config --global user.name "Ваше Имя"
git config --global user.email "почта@example.com"

Полезные настройки для Windows (кириллица в путях и переносы строк):

git config --global core.autocrlf true
git config --global core.quotepath off
git config --global init.defaultBranch main

2.2. Node.js LTS

Сборка проекту не нужна, но Node даёт локальный сервер (npx serve) и линтеры. Ставьте LTS-версию: 

winget install --id OpenJS.NodeJS.LTS -e --source winget
node -v
npm -v

Альтернатива без Node: если есть Python — python -m http.server 5173 из папки проекта. Или просто откройте index.html двойным кликом (всё работает, но карта Яндекса на file:// может ругаться на ключ).

2.3. VS Code

winget install --id Microsoft.VisualStudioCode -e --source winget

Проверка из PowerShell:

code --version

Рекомендуемые расширения:

code --install-extension esbenp.prettier-vscode
code --install-extension dbaeumer.vscode-eslint
code --install-extension ritwickdey.liveserver
code --install-extension ms-vscode.powershell

macOS: brew install git node, VS Code — с сайта code.visualstudio.com. Linux (Debian/Ubuntu): sudo apt install git nodejs npm.

3. Клонирование репозитория

  1. Создайте папку для проектов, например D:\Projects.
  2. В PowerShell:
cd D:\Projects
git clone https://github.com/ka2106/b0s.git
cd b0s

Проверка:

git status
git log --oneline -5

Должно быть On branch main и nothing to commit, working tree clean. Открыть проект в VS Code: 

code .

4. Ключ Яндекс.Карт

Ключ уже вшит в проект — он лежит в config.js и работает у всех посетителей без ввода. На новом устройстве ничего настраивать не нужно, достаточно склонировать репозиторий. Ничего вводить на вкладке «Карта» не придётся. 

// config.js
window.BOS_CONFIG = {
  mapsApiKey: "ваш-ключ-javascript-api",
  mapsDailyLimit: 100,
};
Ключ публичный — файл лежит в открытом репозитории. Для JavaScript API это норма: Яндекс всё равно отдаёт ключ в исходниках страницы, а защита строится на ограничении по HTTP Referer. Поэтому в кабинете developer.tech.yandex.ru у ключа продукта «JavaScript API» должны быть разрешены все домены, с которых открывается дашборд: ka2106.github.io, paragulgov.ru, а для локальной разработки — localhost и 127.0.0.1. Если домена нет в списке, API отвечает Invalid API key; после правок ключ активируется до 15 минут.
Бесплатный тариф — около 100 загрузок карты в сутки; приложение считает их локально (localStorage["bos_map_usage"]) и после лимита останавливает автозагрузку — рядом есть кнопка принудительной загрузки.
Не открывайте дашборд как файл (file://): у такого запроса нет Referer, и Яндекс отклоняет ключ. Для локальной работы используйте http://localhost:5173.

Если ключ нужно заменить (ротация), правится одна строка в config.js — больше нигде ключ не дублируется. Если config.js отсутствует или пуст, вкладка «Карта» покажет поле для ввода ключа и запомнит его в браузере.

5. Запуск и проверка

Из папки проекта (любой из вариантов):

# вариант 1: Node
npx serve -l 5173 .

# вариант 2: Python
python -m http.server 5173

# вариант 3: расширение Live Server в VS Code
# правый клик по index.html → Open with Live Server

Откройте http://localhost:5173 и проверьте:

  • Дашборд — загружается без ошибок, KPI «Всего объектов» = 68;
  • Таблица — «Реестр объектов 185 из 185», сортировка по клику на заголовок;
  • фильтры в сайдбаре: ФО, Объект, Категория, Статус, Год РВ;
  • клик по KPI «Сдано в …» / «Осталось сдать» открывает таблицу с фильтром по году;
  • клик по году на графике «Сдача площадей» — тот же drill-down;
  • Карта — 68 маркеров (плитки появятся только с валидным ключом);
  • Сравнение — загрузите два файла .xlsx и нажмите «Сравнить»;
  • Экспорт в Excel — скачивается файл с листами «Сводка» и «Выборка».

Если консоль браузера (F12) чистая — окружение настроено верно.

6. Как работать с Git

Правило: main — всегда рабочая версия. Любая доработка — отдельная ветка от main, затем merge (или Pull Request) обратно в main.

Обычный цикл работы

# 1. обновить main
git switch main
git pull

# 2. новая ветка под задачу
git switch -c feature/kpi-by-object

# 3. правки в файлах... затем
git status
git add index.html app.js styles.css
git commit -m "feat: KPI по объектам"

# 4. выложить ветку
git push -u origin feature/kpi-by-object

Далее на GitHub — Pull Request в main, просмотр diff, Merge.

Если работаете один и без PR

git switch main
git merge --no-ff feature/kpi-by-object
git push
git branch -d feature/kpi-by-object
git push origin --delete feature/kpi-by-object

Полезное

git log --oneline --graph --all -20   # история
git diff                              # что изменено, но не добавлено
git restore index.html                # отменить правки в файле
git switch main                       # вернуться на основную ветку

7. Вход в GitHub

При первом git push Git спросит учётные данные. Варианты:

  1. Git Credential Manager (ставится вместе с Git для Windows) — откроется окно браузера, войдите в аккаунт ka2106, токен сохранится в системе.
  2. GitHub CLI (удобно для PR и issues): 
    winget install --id GitHub.cli -e --source winget
gh auth login --web
  3. Личный токен (PAT): GitHub → Settings → Developer settings → Personal access tokens → Fine-grained tokens → доступ к репозиторию b0s, права Contents: Read and write. Этот токен вводится вместо пароля.

Проверка доступа:

git ls-remote origin

8. Данные: Google-таблица, кэш, автообновление

Источник данных — публичная Google-таблица, которая читается через gviz-эндпоинт. Настройки лежат в начале app.js в объекте CONFIG:

Параметр Смысл
sheetId ID таблицы из её URL (между /d/ и /edit)
sheetName Имя листа, по умолчанию data
cacheTtlMs Сколько живёт локальный кэш данных (10 минут)
autoRefreshMs Автообновление каждые 5 минут
mapsDailyLimit Дневной лимит загрузок карты (100)

Чтобы сменить источник: скопируйте ID новой таблицы в sheetId (лист должен быть открыт на чтение по ссылке). Кнопка «Обновить» в шапке сбрасывает кэш и перезагружает данные.

9. Необязательно, но полезно

Форматирование и линт

npx prettier --check .
npx prettier --write .

В VS Code удобно включить форматирование при сохранении: Settings → editor.formatOnSave = true, editor.defaultFormatter = esbenp.prettier-vscode.

Валидация HTML (по желанию)

npx html-validate index.html

Проверка синтаксиса JS без запуска

node --check app.js

10. Частые проблемы

Симптом Что делать
Таблица не грузится, в консоли CORS/403 Проверьте, что лист Google открыт «Все, у кого есть ссылка — Читать», и что sheetId/sheetName верные. Открывайте через http://localhost:5173, а не двойным кликом по файлу.
Карта пустая, «Invalid API key» Ключ не от продукта «JavaScript API» либо домен не разрешён в его настройках. В Яндекс.Картах: продукт JavaScript API, в ограничениях HTTP Referer — localhost, 127.0.0.1, ka2106.github.io. После правок ключ активируется до 15 минут. Дашборд должен открываться с http://localhost:5173, а не как файл.
Карта не грузится после нескольких перезагрузок Исчерпан дневной лимит 100 загрузок: подождите до следующих суток или нажмите кнопку принудительной загрузки (счётчик хранится в localStorage).
Правки «пропали» после редактирования VS Code держал старый буфер файла и перезаписал его при сохранении. Всегда проверяйте git diff перед коммитом; если файл меняли не в редакторе — сделайте Revert File и перезагрузите окно.
git push просит пароль и отвергает его GitHub не принимает пароль аккаунта. Нужен PAT (шаг 7) или вход через Git Credential Manager.
Кракозябры в выводе Git chcp 65001 в PowerShell или core.quotepath off
