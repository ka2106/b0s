# Правила работы над проектом

Короткая памятка: как вести задачи, чтобы не тратить лишний контекст и не делать лишних действий.
Дополняет `docs/HANDOVER.md` (карта проекта) и `.github/copilot-instructions.md` (инструкции агенту).

## 1. Экономия токенов

- Не читать файлы целиком: сначала `grep`/поиск, потом `view` с диапазоном строк.
- Не перечитывать то, что уже есть в контексте этой сессии.
- Браузер: `page.evaluate` с маленьким JSON вместо снимков страницы; скриншот — только когда нужно увидеть UI.
- Длинные выводы (`git diff`, логи) — в сжатом виде: `--stat`, первые N строк, `Select-String`.
- Правки — батчем (`edit` ×N в одном ответе), затем одна проверка (`node --check app.js`),
  а не перечитывание файла после каждой строки.
- Не переизмерять производительность карты: цифры и выводы — в `docs/HANDOVER.md`.
- Если контекст вырос до ~60–80k токенов — зафиксировать состояние в `docs/HANDOVER.md`
  и продолжить в новом чате.

## 2. Согласование действий (обязательно)

Любое действие, особенно потенциально объёмное, — сначала короткий план
(что / зачем / риск / что проверить) и явное «да» владельца.

Объёмное:

- выкатка в прод (`push` в `main`, GitHub Pages);
- правки больше ~50 строк или больше одного файла кода, рефакторинг;
- новые файлы и изменения UX/поведения;
- установка пакетов, тестовые стенды, замеры производительности;
- всё, что требует ручной проверки владельцем.

Без согласования можно: чтение и поиск по коду, мелкие правки внутри уже согласованной задачи,
обновление документации по ней.

## 3. Коммиты, пуши, деплой

- **Коммиты и пуши — только по явному согласованию.** Без «да» правки остаются в рабочем дереве.
- Деплой (Pages собирается из `main`) — отдельное согласование, даже после коммита.
- Сообщения коммитов: русский язык, тело-список, трейлер `Co-authored-by`.
- Ветки: `feature/...` / `fix/...` → `git merge --ff-only` → `push` (после согласования).

## 4. Проверки

- После правок: `node --check` для всех скриптов (`app.js`, `coords.js`, `debug-hud.js`,
  `excel-loader.js`); при изменениях данных — тестовые ориентиры из
  `docs/HANDOVER.md` (на 25.11.2026: 78 объектов, 185 строк, 135 этапов, 50 АБЧ).
- Документация — без сборки и прогонов.

## 5. Данные и решения

- Источник — публичная Google-таблица (gviz); координаты площадок — `cityCoords` в `app.js`.
- Правило «этап vs АБЧ» живёт в одном хелпере `isAbchRow` — менять только там.
- Ключ Яндекс.Карт в `config.js` публичный по замыслу, ограничен HTTP Referer.
- Вопрос «карта фризит при зуме» закрыт/отложен (24.11.2026): новое расследование — только
  по просьбе владельца и со скриншотом панели `?debug=1`.
